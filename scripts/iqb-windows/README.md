# IQB Windows Application Checks

This is a pilot for IQB-Kodieren, with download auditing and the same Windows
startup probe also available for itc-ToolBox. It does not test the Kodierbox web app.

## Current Evidence

On 2026-10-04, the live IQB catalogue offered IQB-Kodieren 4.3.0.3 and
itc-ToolBox 3.3.0.2. Both packages passed 56 download checks in total, including
ClickOnce provider URLs, manifest sizes, and SHA-256 hashes of all payload files.
The other five applications in the descriptive catalogue had no current download.
Download availability is separate from successful Windows installation.

This Mac is ARM64. No local Windows VM was found, and the system volume had only
about 1.4 GiB free. Windows installation and GUI tests have therefore not run.
The Parallels download was stopped before installation and its incomplete download
removed. A Windows VM needs substantially more available host storage. Existing
user files were left untouched.

## Mac Commands

Run from the repository root:

```sh
npx nx run iqb-windows-checks:audit
npx nx run iqb-windows-checks:test
npx nx run iqb-windows-checks:test-runner
npx nx run iqb-windows-checks:verify-bundle
npx nx run iqb-windows-checks:package
```

Reports, versioned Windows binaries, and `iqb-windows-testkit.zip` are generated
in `tmp/iqb-windows`, which is already ignored by Git. Packaging checks all file
hashes again. The ZIP contains only the audited files and the Windows probe;
it contains no repository credentials or coding data.

`probe-host` attempts the Windows probe on the current host. On macOS it records
`blocked`, keeps functional tests at `not-run`, and returns a nonzero exit code.

## First Windows Run

Use an existing Windows 11 PC/VM, or provision a Windows 11 ARM VM in Parallels
after sufficient Mac storage is available. Windows is licensed separately from
Parallels. Log in to Windows and keep its desktop unlocked. Do not run the GUI
probe as a Windows service or from a locked RDP session.

Extract `iqb-windows-testkit.zip` into a writable local Windows directory. Use
ordinary Windows PowerShell in that directory:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Bootstrap-Windows.ps1 -Install
```

The script installs user-scoped Python 3.11 x64 via winget if it is missing,
creates an isolated Python environment, verifies the bundle, and starts the
original IQB installer. Complete any installation dialogs and close IQB-Kodieren.
Internet access to the IQB download sites is still necessary for ClickOnce.
The script does not change the system execution policy.

Then inspect the installed application:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Bootstrap-Windows.ps1 -Inspect
```

For itc-ToolBox, add `-App itc-ToolBox` to each command. For an explicitly separate
portable-binary experiment, add `-Launch bundle` to the inspect command; this
does not test ClickOnce installation. The normal probe launches the installed
ClickOnce shortcut and rejects a running executable different from the audited
version. If ClickOnce updates the app, perform a new audit and regenerate the kit.

The probe records host architecture, .NET version, application version, a window
screenshot, UIA and Win32 control inventories, and resolved Python package
versions under `artifacts/<application>`. The visible main-window title must
contain `Kodieren` or `ToolBox`, respectively; a generic runtime error dialog does
not count. At least one backend must expose child controls, and the application
must exit when its window is closed. `smoke-passed` proves startup, UI inspection,
and shutdown only. Installation may
still require operator interaction, and these Windows code paths remain untested
until the first Windows run.

## Functional Tests And Repeatability

`functional-test-plan.json` records the pending assertions. The IQB manual says
that jobs are ZIP files containing scans and XML control data, generated by
IQB-ScanManager. Coding results use an internal result-file format and are saved
automatically. A valid anonymized job and independently known expected results
are needed before a reliable coding, persistence, and result comparison test can
be implemented. These inputs and actual GUI selectors are deliberately unset.

Once the pilot works, take a clean VM snapshot, keep a pristine copy of each job,
and test with a fresh working copy. Preserve reports/results outside the VM before
restoring a snapshot. Run the same scenarios on Windows 11 x64 to make claims
about standard Windows PCs. For CI, run the runner in the logged-in interactive
desktop session and arrange snapshot restoration outside that runner.
